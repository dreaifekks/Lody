# 看板工具、提示与共享笔记

Status: implemented

[English](2026-10-15-board-tools-notes.md)

## 摘要

看板成员需要共享记录，并让工具权限始终跟随当前成员资格。PR2 增加经守护进程路由的
看板查询和 LoroText 笔记、按角色追加的启动提示，以及新线程和成员操作入口。并发追加
通过文本合并保留双方内容，不再覆盖同一条 Flock 行。容量按每次本地写入限制；自动回报
和交接在 PR3/PR4 实现前明确标为尚不可用。

## 决策与归属

本次接续 [PR1](2026-10-15-board-overview.zh.md)，实现
[设计中的 PR2 范围](../../../../specs/project-coordinator/design.zh.md#pr2-已实现)。

```text
ACP 启动元数据 -> HTTP 头 / stdio 环境变量 -> 展示看板工具
Session 工具调用 -> 守护进程活跃回合校验 -> 当前成员资格 -> 看板行 / 笔记
Overview 笔记面板 -> shared LoroText 写入 -> 已有 repo 持久化与房间同步
```

- shared 负责文档命名、文本操作和字节上限；CLI 打开/同步文档，渲染端管理面板订阅。
  不新建守护进程副本或注册表。
- 请求头不授予权限；替换同时检查 `boardRole` 和看板行的协调者 id。守护进程在文档同步
  后、写入前重新检查成员资格。
- 手动成员操作仅影响选中的会话，协调者固定。新线程复用 Agent/Role 控件和正常接受流程，
  使用 chat 上下文；线程选择不覆盖记住的协调者选择。
- 提示只承诺当前能力。普通 Operation 回执继续工作；自动看板回报、轮数拒绝和交接尚未
  实现，不让 agent 等待不存在的通知。
- Overview 工具沿用折叠行的元数据/presence，最多 100 行、64 KiB；历史详情按需读取，
  保留 PR1 的文档获取边界。
- 本地 UTF-8 容量检查不能充当分布式锁。并发合并超限仍保留双方内容，后续追加被拒绝，
  允许替换为更短文本。

## 评审修正

创建和工具读写曾把 hub 同步作为硬前置，导致本地副本完整时仍会随网络失败。
现在沿用已有设置读取的模式：尝试同步，失败仅记录警告，继续读取本地副本；工具一次
调用只刷新一次目录，笔记写入前仍重新读取本地成员资格。本地持久化与后台上传的边界不变。
协调者判定和默认标题使用调用上下文的 session id，允许元数据缺少 id。协调者提示明确
约束由 Lody 自动附到线程首条消息，无需转述；缺失看板行走 `Effect.fail`。

测试扩展现有套件：同步明确拒绝时通过真实守护进程工具路由读写笔记，并覆盖稀疏元数据；
执行服务实际发送给 ACP 的载荷覆盖成员/非成员、协调者/线程和续接不重复注入；新线程
对话框提交到 `startSession` 的载荷带 boardId、不带 boardRole/project，成功后关闭表单。
