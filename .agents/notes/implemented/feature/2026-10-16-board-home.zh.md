# 看板主界面：打开看板就是打开协调者对话

Status: implemented
Translation: current

[English](2026-10-16-board-home.md)

## 摘要

第一版看板界面是一个独立的管理页，用户不会把它当成干活的地方。现在打开看板和打开对话一样：
侧边栏把看板和对话并列，打开后是协调者对话，旁边是放线程和文件的看板侧面板；不常用的设置
收进浮窗。面板复用会话侧面板机制，线程在面板里打开，但不变成 Side Chat。线程行只用元数据
和 presence，所以失败的线程在打开后、以及协调者收到的回报里才看得到，列表里不显示。

## 决定与依据

[设计文档](../../../../specs/project-coordinator/design.zh.md)的「看板主界面」一节记录了
用户 2026-10-16 的决定。本文对应第 1、2 步。

- **协调者就是看板。** 协调者的会话页增加 `board` 侧面板类型。单独做一个看板页，就得
  另做对话、输入框、面板布局和移动端抽屉，而会话页这四样都有了。`/boards/<id>` 保留为
  别名，带 `?board=1` 跳转。渲染阶段的恢复照搬 `?pr`：每个会话一个状态守卫，用完从 URL
  去掉，所以从侧边栏再次打开看板时还会生效。
- **线程不用 Side Chat 的 id。** Side Chat 的关闭路径会终止并删除会话，渲染路径也只接受
  本页的侧面板子会话。所以看板面板直接渲染 `SessionChatInterface`，把线程本身作为它的
  工作区会话（否则会显示协调者的仓库、PR 和 diff 状态），并且不传本页的文件和 diff 处理
  函数，因为它们绑定在协调者上。打开的是哪个线程存在页面状态里，因为紧凑布局会重挂面板。
- **在各列表的数据源处过滤。** `sessionListAtom` 和 `useVisibleSessionMetas` 还供命令面板、
  完成通知、PR 监视、提及和 Dock 计数使用，它们仍要看到协调者。侧边栏、移动端首页和归档页
  各自过滤。由被隐藏的协调者打开的会话，通过已有的 opened-by 树退回为顶层行。
- **侧边栏标记不加订阅。** `LoroAppSidebar` 已经维护一份引用稳定的实时状态映射；
  `boardActivity` 读它，等待判断和 `deriveBoardSessionStatus` 一致。
- **行不读文档。** PR1 只在展开的行上打开成员文档。面板没有展开；为了找失败而打开每个成员
  的文档，会破坏按需读文档的边界。状态来自 `sessionLiveStatusAtomFamily` 上的一个派生 atom
  加元数据。
- **归档与恢复。** 会话归档本来就包含协调者打开的会话；恢复只包括直接的子 Tab。所以归档
  依次处理协调者和每个成员根会话，再标记看板行；恢复时像创建一样在 catalog writer 里重新
  检查 50 个上限，逐个恢复根会话，最后才清掉标记。第一版先清标记，某个成员恢复失败时，
  看板已经离开归档页，再也没有恢复入口。现在看板行两个方向都最后改：失败时看板留在原处，
  入口（归档页或设置）还在，可以重试，提示里写明原因。不做事务或回滚，重试会跳过已经
  成功的部分。两个恢复同时读到 49 个未归档看板的情况，设计里已经接受：上限检查本来就不是
  分布式事务。
- **同一个会话只有一个界面。** 子 Tab 会继承看板，所以协调者自己的子 Tab 和 Side Chat 也是
  线程，而会话页已经挂着它们。之前在面板里打开会再建一个 `SessionChatInterface`，输入框
  草稿各存一份。现在协调者的直接子会话在会话页里打开：子 Tab 切换主区的 Tab，Side Chat
  切到它的侧面板 tab。聚焦输入框、查找这类命令按用户所在的区域选目标：焦点在可见的看板
  面板里时，作用于面板中打开的线程。
- **面板绑定看板。** 会话页在会话之间不重挂，所以在 A 打开的面板会把 tab 和设置草稿带到 B，
  保存时把 A 的草稿写进 B，还把 B 的协调者改了名。现在 `BoardSidePanel` 按工作区和看板 id
  给内容设 key，设置浮窗也按看板 id 设 key。
- **入口。** 所有看板入口（侧边栏、`/boards/<id>`、命令面板）都用 `boardEntrySearch` 明确写入
  协调者自己的 Tab；以前不带 `?tab`，路由会恢复上次选中的子 Tab，比如 reviewer。命令面板的
  数据源仍保留协调者，搜到时显示看板名和看板图标。
- **命名。** 在看板页上，会话侧面板的「文件」改叫「工作区文件」，看板面板里的 tab 叫
  「看板文件」；侧面板框架不变。
- **设置的范围。** 浮窗只编辑现在就生效的字段：名称、目标、规则。项目范围、看板记忆、
  每日摘要在各自的步骤实现前不显示。协调者的模型仍在它的输入框里选。改名时同步改协调者
  会话的标题，让标签和窗口标题一致。

## 验证与限制

- 测试：`packages/components/tests/board-overview.test.tsx` 在元数据和 presence atom 上挂
  真实的侧面板，检查分组、排除协调者、继承祖先的停止、presence 优先于过期状态、打开线程和
  笔记编辑器；另外覆盖侧边栏标记、新建对话框的默认名称和规则。设置、归档、恢复走真实的
  会话动作，会话元数据放在 `LoroRepo` 里：设置写入和协调者改名、设置草稿未保存时切换看板、
  某个成员写入失败时的归档和恢复（看板留在原处，重试后完成）。另有一个协调者页面的替身，
  在真实面板打开协调者子 Tab、Side Chat 和独立线程时，按会话数界面个数。
  `SessionChatInterface` 本身离开完整运行时无法在 jsdom 里挂载，所以两边都用一个标记代表
  一个界面。三条新用例在撤掉对应修复后都会失败。`workspace-catalog-write.test.ts` 覆盖恢复
  时的上限和成员失败，`session-draft-tabs.test.ts` 覆盖持久化的 `board` 面板。
- Storybook `Workspace/Boards` 用合成数据渲染真实的侧边栏、会话布局、标签栏、面板、设置
  和新建对话框，在 1440px 和 390px 下检查过。
- 未验证：完整的桌面应用（构建机没有显示器）、手机抽屉的手势、LAN 上的表现。共享目录在
  第 4 步之前只是占位。
